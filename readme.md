# Standard Guide for Molecular Biology Project Structuring and Documentation

This repository defines the file structure, workflow, and digital documentation standards recommended for molecular biology research projects, ensuring full traceability, reproducibility, and compliance with the **FAIR** (*Findable, Accessible, Interoperable, Reusable*) principles.

---

## 2. Digital Documentation & ELN Workflow

To preserve research integrity, all laboratory activities follow these core documentation rules:

### 2.1. Electronic Lab Notebook (ELN - eLabFTW / Benchling) Logging

1. **Standard Naming Convention:** Every registered experiment must begin with a unique identifier formatted as `EXP-[AREA]-[YEAR]-[ID]` (e.g., `EXP-BM-2026-088`).
2. **Standardized Templates:** Unstructured plain text entries are prohibited. All entries must utilize the pre-defined Markdown templates located in `docs/sops/`.
3. **Reagent Traceability:** Researchers must link lot numbers, enzymes, aliquot IDs, and freezer locations managed within the ELN inventory module.
4. **Digital Signatures & Immutability:** Upon experiment completion, the entry must be **digitally signed** in the ELN platform. Subsequent modifications require creating a new linked record.

### 2.2. Raw and Processed Data Management (`data/`)

* **Raw Data Immutability Rule (`data/raw/`):** Original files generated by instruments (sequencers, spectrophotometers, gel imagers) **must never be edited or overwritten**.
* **Symbolic Links & Cryptographic Hashes:** Because raw sequencing files often exceed gigabyte thresholds, the ELN record must store the SHA-256 hash alongside the physical or cloud storage path.

### 2.3. Code Control and Reproducibility (`src/` & `notebooks/`)

* All bioinformatic analyses must be fully reproducible using executable R, Python, or workflow scripts (Nextflow/Snakemake).
* Software package dependencies must be locked in environment definition files (`environment.yml` or `requirements.txt`).

## 3. Data Privacy, Access Control, and IP Protection

To balance open collaboration with intellectual property safeguards:

1. **Role-Based Access Control (RBAC):** Ongoing experimental entries remain private to the author and the Principal Investigator (PI) until validated.
2. **Internal Protocol Sharing:** Approved SOPs transition to "Internal Group Access" to streamline lab practices.
3. **Git Version Control Safeguards:** Patient identifiers, proprietary sequences, and sensitive clinical metadata are strictly excluded from public tracking via `.gitignore`.

## 4. Onboarding Checklist for New Laboratory Members

Before commencing wet-lab or computational experiments:

* [ ] Request access to the institutional ELN platform (eLabFTW / Benchling).
* [ ] Clone this repository and configure the local software environment.
* [ ] Review the core SOPs located in `docs/sops/`.
* [ ] Complete a trial entry linking test inventory and generating a digital signature.
